# BRIDGET LAB（ブリジット攻略wiki）

Astro + Starlight で作った静的サイトです。bot 本体（リポジトリ直下）とは独立しています。

```bash
cd wiki
npm install
npm run dev      # http://localhost:4321 で確認
npm run build    # dist/ に出力
```

## サイト上から記事を書く

**見るだけならログイン不要**です。記事の作成・編集・削除にはログイン（メールのワンタイムPIN）が必要です。コメント・いいね・お気に入りはログインしなくても使えます（→「ゲスト」）。

サイドバーの「＋ 記事を書く」、各一覧の「＋ 記事を書く」、記事ページの「編集」からフォームを開けます（未ログインならログイン画面が出ます）。ログインした人なら誰でも作成・編集・削除できます。

- 保存すると GitHub の `main` に記事ファイル（`.md`）としてコミットされ、Cloudflare Pages が自動で作り直します（**反映まで1〜2分**）。
- 動画はURLを貼るか、ファイル（mp4 / webm / mov、**10MBまで**）をアップロード。アップロードした動画は R2 に保存されます。
  - 記事から外したり記事を削除すると、**ほかの記事で使っていなければ**一緒に消えます。
  - アップロードしたまま保存しなかった動画は、フォームで × を押すとすぐ消え、放置したものも24時間後に自動で消えます。
- コンボ・起き攻め・セットプレイ・キャラ対策・Q&A では、既存の練習方法を選ぶか、練習方法の記事をその場で同時に作れます。
- URL（カテゴリ・立ち位置・URL名）を変えると、コメント・いいね・お気に入りは新しいURLへ引き継がれます。練習方法の記事はURLを変えられません。
- 同じ記事を2人が同時に編集・保存した場合、後から保存した方に「読み込み直してください」と出ます（先の人の変更を上書きしません）。
- 誰がいつ変更したかは D1 の `article_log` テーブルに残ります（GitHub のコミットにはメールアドレスを入れません）。
- 本文に書いたHTML（`<b>` など）はタグとして扱わず、文字のまま表示します（スクリプトを埋め込まれないようにするため）。
- フォームで編集できるのは `.md` の記事です（一覧ページなどの `.mdx` は対象外）。

## 記事の書き方（ファイルで直接）

`src/content/docs/<カテゴリ>/` に `.md`（コンボ表示を使うなら `.mdx`）を置きます。

| カテゴリ | フォルダ |
| --- | --- |
| 基本戦略 | `basics/` |
| 立ち回り | `neutral/` |
| コンボ | `combos/center/`, `combos/corner/` |
| 起き攻め | `okizeme/center/`, `okizeme/corner/` |
| セットプレイ | `setplay/center/`, `setplay/corner/` |
| キャラ対策 | `matchups/` |
| 練習方法 | `training/` |
| Q&A | `faq/` |

### フロントマター

```yaml
---
title: 2K始動 基本コンボ
description: 一覧に出る説明文
versions: ["2.02", "2.04"]   # 使えるバージョン（複数可・あとから追記）
position: center       # center（画面中央） / corner（画面端）
starter: 2K            # 始動技
counterHit: false      # カウンターヒット前提なら true
damage: 142            # 任意
difficulty: 1          # 1〜5（任意）
opponent: ソル         # キャラ対策のみ
videos:                # 動画（YouTube / X / mp4 のURL。複数可・任意）
  - https://www.youtube.com/watch?v=xxxxxxxxxxx&t=42s
  - url: https://example.com/clip.mp4
    title: 端バージョン
combos:                # コンボパーツ（動画なしでも付けられる。複数可・任意）
  - 2K > 2D > 236K
  - route: 2K > c.S > 2H > 236S
    damage: 168
    tension: 15
    note: 補足
training: [hit-confirm] # 紐づける練習方法の記事（training/ 以下のファイル名）
tags: [初心者向け, 運び]
---
```

### バージョン管理

- `src/site.config.ts` の `VERSIONS` に、管理するバージョンを古い順に並べます。新しいパッチが出たら末尾に1つ足すだけで、それが「現行」になります。
- 記事の `versions` に、使えるバージョンを並べます。飛び飛びでもOKです（例：2.03で消えて2.04で復活 → `["2.02", "2.04"]`）。
- `versions` に現行バージョンが入っていない記事は old 扱いになり、サイドバーに `old` バッジ、本文上部に警告が出ます。
  - 新しいパッチが出たら、確認できた記事から `versions` に追記していきます。
  - 管理開始時点で使えないものは `versions: []` にします。
  - バージョンに関係しない記事は `versions` を書きません（常に表示）。
- 一覧の絞り込みで「Ver.〇〇 で使える」を選ぶと、そのバージョンが `versions` に入っている記事だけになります。
- `VERSIONS` に無いバージョンを書くとビルドエラーになるので、打ち間違いに気づけます。

### 動画・コンボパーツ

- `videos` はURLの種類を自動で判定します（YouTube・YouTube Shorts・X の投稿・mp4/webm/mov ファイル）。それ以外のURLはリンクとして表示します。
- 1本目の動画は一覧のカードにも表示され、カード上でそのまま再生できます（音なし）。
- 本文に `![タイトル](動画URL)` と書くと、**その位置に動画を置けます**（見出しの下など）。続けて書いた動画は横に並びます。
  - 本文に置いた動画も `videos` に入れておきます（一覧カードのサムネは `videos` の1本目。本文に置いた動画は記事上部の一覧には出ません）。
  - 本文にしか書いていないアップロード動画も「使用中」として扱われ、削除されません。
- `combos` の1つ目は一覧のカードにも小さく表示されます。

### 練習方法との紐づけ

- コンボ・起き攻め・セットプレイ・キャラ対策・Q&A の記事に `training` を書くと、記事の下に「この記事の練習方法」が出ます。
- 練習方法の記事には、紐づけている記事が「この練習で身につく記事」として自動で並びます。
- 存在しない記事や、紐づけできないカテゴリから指定するとビルドエラーになります。

### いいね・お気に入り

- 全カテゴリの記事に 👍（いいね）と ★（お気に入り）が付けられます。ログインしなくても押せます。誰が押したかは、ログインしていればメールアドレス、ゲストならブラウザごとのIDで区別します（画面には出ません）。
- いいねの数はみんなに見え、一覧で「いいねが多い順」に並べ替えられます。
- お気に入りは本人だけのもので、一覧の「お気に入りのみ」やサイドバーの「★ お気に入り」で絞り込めます。

### ゲスト（ログインしていない人）

- いいね・お気に入り・コメントは、ログインしなくても使えます。記事を開いたときに、ブラウザへランダムなIDのクッキー（`__Host-bl_anon`、約400日）を付けて、そのIDで区別します。
  - クッキーを消したり別の端末・ブラウザで開くと、別の人として扱われます（お気に入りが見えなくなる、自分のコメントを消せなくなる）。
  - そのブラウザでログインすると、ゲストのときのいいね・お気に入り・コメントを**アカウントへ引き継ぐか聞きます**（共用のPCで、前の人のデータを取り込まないように）。答えるとゲストのIDは消えます。
  - ゲストのいいねは、同じIPアドレス（IPv6 は /64 単位）から1時間に60件までです。クッキーを消して押し直す水増しを抑えます（完全には防げません）。
- ログインしたまま開いていた画面でログインが切れていると、書き込みは行わずに「ログインし直しますか？」と聞きます（ゲストとして書き込まれて、取り消したはずのものが残るのを防ぐため）。
- ゲストのコメントには次の対策があります。
  - Cloudflare Turnstile（人間かどうかの確認）を通ったものだけ受け付けます。`TURNSTILE_SITE_KEY` と `TURNSTILE_SECRET_KEY` が無いと、ゲストはコメントできません（ログインの案内が出ます）。
  - 連投の制限：同じブラウザは30秒に1件、同じブラウザか同じIPアドレスで1時間に10件まで。制限の確認と書き込みは1つのSQLで行うので、同時に送っても超えられません。
  - コメントには「ゲスト」の印が付きます。
  - `ADMIN_EMAILS` に書いた人は、ログインするとどのコメントでも削除できます。
- IPアドレスはそのまま残さず、鍵付きハッシュにして記録します。鍵は初回に自動で作って D1 の `app_keys` に置きます（Turnstile の鍵とは別なので、そちらを入れ替えても制限の記録はリセットされません）。
- ログインしている人には、確認も回数の制限もありません。

## 公開（Cloudflare Pages）

すべてCloudflareのダッシュボード上で設定します（`wrangler.toml` は置かない）。

1. **D1**：ストレージとデータベース → D1 → `bridget-wiki` を作成 → コンソールで `functions/schema.sql` の中身を全部実行
   - 前から使っているデータベースには、`schema.sql` ではなく `functions/migrations/` の SQL のうち未実行のものを古い順に実行します（`schema.sql` を丸ごと流すと途中でエラーになります）
     - `2026-11-guest.sql`、`2026-11-guest-2.sql`：ゲスト対応
2. **R2**：R2 オブジェクトストレージ → バケットを作成 → `bridget-wiki-media`
3. **GitHub のトークン**：GitHub → Settings → Developer settings → Fine-grained tokens → Generate new token
   - Repository access: このリポジトリだけ
   - Permissions: **Contents = Read and write**（ほかは不要）
4. **Pages**：Workers & Pages → 作成 → Pages → Gitに接続 → このリポジトリ
   - フレームワーク: Astro / ビルドコマンド: `npm run build` / 出力: `dist` / ルートディレクトリ: `wiki`
   - 環境変数: `NODE_VERSION` = `22`
5. **Pagesの設定 → 変数とシークレット**
   - `GITHUB_REPO` = `hachiju88/ggst-discord-tool`（テキスト）
   - `GITHUB_BRANCH` = `main`（テキスト）
   - `GITHUB_TOKEN` = 3 で作ったトークン（**シークレット**）
   - `ACCESS_TEAM_DOMAIN` = Zero Trust のチームドメイン（例 `myteam.cloudflareaccess.com`。Zero Trust → 設定 → カスタムページ などで確認）（テキスト）
   - `ACCESS_AUD` = 7 で作る Access アプリケーションの「アプリケーション オーディエンス (AUD) タグ」（テキスト。複数ならカンマ区切り）
   - `TURNSTILE_SITE_KEY` = 8 で作る Turnstile のサイトキー（テキスト）
   - `TURNSTILE_SECRET_KEY` = 8 で作る Turnstile のシークレットキー（**シークレット**）
   - `ADMIN_EMAILS` = どのコメントでも削除できる人のメールアドレス（テキスト。複数ならカンマ区切り）
6. **Pagesの設定 → バインディング**
   - D1 データベース：変数名 `DB` → `bridget-wiki`
   - R2 バケット：変数名 `MEDIA` → `bridget-wiki-media`
   - 追加したら「デプロイ」→ 最新の「…」→「デプロイを再試行」
7. **Access**：Zero Trust → Access → アプリケーション → セルフホスト
   - 守るのは**ログインの入口だけ**（サイト本体は誰でも見られる）：
     - `<プロジェクト名>.pages.dev` パス `login`
     - `<プロジェクト名>.pages.dev` パス `edit`
     - `*.<プロジェクト名>.pages.dev`（プレビュー用のURL。パスなし＝全体を守る）
   - ポリシー: 許可 / 書き込みを許す人のメールアドレス（だれでも良ければ「すべての人」）/ ログイン方法: ワンタイムPIN
   - 作ったアプリケーションの「概要」にある **AUD タグ**を、5 の `ACCESS_AUD` に入れて再デプロイ
8. **Turnstile**（ゲストのコメント用）：Cloudflare ダッシュボード → Turnstile → ウィジェットを追加
   - ホスト名：`<プロジェクト名>.pages.dev`（独自ドメインを使うならそれも）/ モード：管理（推奨）
   - 出てきたサイトキーとシークレットキーを 5 に入れて再デプロイ（入れるまでは、ゲストはコメントできず、いいね・お気に入りだけ使えます）

ログインの流れ：`/login`（Access で保護）に来ると、Access が付けた JWT を検証して、サイト全体で使う自前クッキー `__Host-bl_auth`（HttpOnly / SameSite=Lax）に入れ、元のページへ戻します。
API（`server/auth.ts`）はこの JWT の署名を毎回検証してメールアドレスを取り出します。書き込みAPIは、自分のサイトから送られたもの（Origin の一致）で、JSON の API は `Content-Type: application/json` のものしか受け付けません（CSRF 対策）。
サイドバーの「ログイン」「ログアウト」から出入りできます（`/logout` は自前クッキーを消して Access のログアウトへ送ります）。
このメールアドレスで、コメントの投稿者・いいね・お気に入り・記事の変更者を区別します（画面には出ません）。ログインしていない人のコメント・いいね・お気に入りは、ゲストのID（`__Host-bl_anon`）で区別します。
`ACCESS_TEAM_DOMAIN` と `ACCESS_AUD` が無いと、全員が未ログイン扱いになります（記事の書き込みはすべて断られ、コメント・いいね・お気に入りはゲストとして扱われます）。
`Cf-Access-Authenticated-User-Email` ヘッダーは、Access を通らないパスでは偽装できるので使っていません。

### 無料枠の目安
- R2（動画）：10GB まで無料。超えても 1GB あたり月 $0.015。配信の転送量は無料
- Pages のビルド：月 500 回まで無料（記事を1回保存するごとに1回）

### 検索避け
- 全ページに `<meta name="robots" content="noindex">`
- `public/robots.txt` で全拒否
- `public/_headers` で `X-Robots-Tag: noindex`
